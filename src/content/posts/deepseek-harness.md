<h2 id="section-1">一、为什么需要 DeepSeek Harness？传统 Agent 框架的致命痛点</h2> <p>随着大语言模型（LLM）推理能力在 2026 年实现飞跃式突破（如 DeepSeek-R1、Claude 3.7 Sonnet 及 GPT-4o 等），开发者对 AI 的期望已经从简单的“对话问答”全面转向<strong>自主解决复杂工程任务的智能体（Autonomous Agents）</strong>。</p> <p>然而，在构建面向真实代码库、终端操作与多步骤复杂任务的 Agent 时，现有的主流开源框架普遍暴露出以下致命痛点：</p> <ul> <li><strong>死板的“巨石核心”设计：</strong>像早期 LangChain、CrewAI 或 AutoGen 等框架，核心调度循环往往被硬编码在庞大的框架底层。开发者想要定制某个循环决策、替换路由逻辑或者介入多轮错误恢复机制时，往往需要痛苦地重写内部类或打 Monkey Patch。</li> <li><strong>状态残留与内存泄漏：</strong>许多 Agent 系统在长时间运行多轮任务后，上下文管理器与工具执行器中残留了大量废弃闭包与中间状态，导致长时间运行容易崩溃，无法安全承载全天候自动化后台任务。</li> <li><strong>工具与模型过度耦合：</strong>部分框架严重绑定某一家专有模型 API 或特定的提示词模板，遇到不同的上下文窗口、原生工具调用格式（Function Calling）或本地推理框架（如 Ollama / vLLM）时，适配成本高昂。</li> </ul> <p>正是在此背景下，DeepSeek-AI 官方开源了 <strong>DeepSeek Harness</strong>（CLI 工具命名为 <code>dsh</code>，开源仓库为 <code>deepseek-ai/deepseek-harness</code>），以彻底解耦的微内核设计为行业树立了新一代 Agent 运行时的标杆。</p> <div class="table-wrapper"> <table class="article-table"> <thead> <tr> <th>对比维度</th> <th>传统 Agent 框架 (如早期巨石框架)</th> <th>DeepSeek Harness (dsh)</th> </tr> </thead> <tbody> <tr> <td><strong>Headless 任务、Web UI、SDK stdio、ACP 协议全支持</strong></td> </tr> </tbody> </table> </div> <h2 id="section-2">二、核心底层原理：基于 Cordis 的“万物皆插件”时空架构</h2> <p>DeepSeek Harness 的核心基石，是名为 <strong>Cordis</strong> 的跨平台微内核框架。如果你接触过现代前端的高性能微内核架构，就会对它的设计拍案叫绝。</p> <p>在 Cordis 的理念中，系统追求极致的<strong>“时空可组合性（Spatio-temporal Composability）”</strong>：</p> <ul> <li><strong>空间解耦：</strong>系统没有任何强制性的“中心 Hub”。模型适配器（Model Adapter）、提示词装配器（Prompt Synthesizer）、工具注册表（Tool Registry）、沙箱执行环境（Execution Sandbox）与前端界面（Web UI）之间，全部通过标准的 Service 接口松耦合通信。</li> <li><strong>时间解耦：</strong>任何插件可以在运行时被动态加载、卸载或重载。当一个插件被卸载时，其挂载的所有事件监听、临时文件句柄、定时器与内存状态会被底层彻底清理，<strong>绝不留下任何状态残留</strong>。</li> </ul> <pre><code class="language-text">┌─────────────────────────────────────────────────────────────────┐ │ DeepSeek Harness 运行时分层架构 │ ├─────────────────────────────────────────────────────────────────┤ │ 交付层 (Profiles) : Web UI ｜ Headless 终端 ｜ SDK stdio ｜ ACP │ ├─────────────────────────────────────────────────────────────────┤ │ 编排层 (Plugins) : Agent 循环 ｜ 工具注册 ｜ 权限校验 ｜ 会话日志 │ ├─────────────────────────────────────────────────────────────────┤ │ 微内核 (Cordis) : 时空可组合服务总线 ｜ 依赖注入 ｜ 资源无残留清理 │ ├─────────────────────────────────────────────────────────────────┤ │ 底层适配 (Adapters): DeepSeek (V3/R1) ｜ OpenAI 兼容 ｜ 本地环境 │ └─────────────────────────────────────────────────────────────────┘</code></pre> <p>最让人震撼的是：<strong>在 dsh 中，连“Agent 执行主循环”自身都只是一个普通插件！</strong>这意味着：如果你想写一个只管审校代码的单步审查 Agent，你可以加载一个极简的单轮循环插件；如果你想跑一个需要自我反思、执行单元测试并根据报错连续修复 10 轮的重度工程 Agent，你只需要切换加载高阶的自主迭代循环插件，而无需重写任何外围代码。</p> <h2 id="section-3">三、分层补丁系统（Layered Patch Architecture）</h2> <p>任何接触过实际生产环境的人都知道，给开发环境配 API Key、给测试环境配只读权限、给 CI/CD 流水线配免交互模式，如果写在一个大配置文件里，维护起来简直是噩梦。</p> <p>DeepSeek Harness 创新性地引入了<strong>分层补丁覆盖机制（Layered Patches）</strong>。系统在启动时，由底向上依次应用配置层，后加载的层以全量行替换（Row-level override）的方式覆盖前面的层：</p> <ol> <li><strong>In-box Bundles（官方基准包配置）：</strong>如 <code>@deepseek-ai/dsh-base</code> 提供的默认工具清单与系统级默认安全规则。</li> <li><strong>Profile Manifest Patch（配置文件补丁）：</strong>每个 Profile 独有的 <code>cordis.patch.yml</code>，例如 <code>web</code> 模式会开启静态资源路由，而 <code>headless</code> 模式会强制输出纯文本。</li> <li><strong>Home-Level Global Preferences（用户全局偏好）：</strong>位于 <code>$DSH_HOME/cordis.patch.yml</code>，这里存放你个人的 DeepSeek API Key、默认编辑器偏好与个人开发习惯。所有 Profile 共享这层底色。</li> <li><strong>CLI Overlays（命令行瞬时注入）：</strong>通过 <code>dsh --patch &lt;path&gt;</code> 在终端启动时临时注入特定的补丁规则，仅对本次任务生效。</li> </ol> <blockquote> <p><strong> 贴心提示：</strong>如果你不确定最终拼装好的完整配置是什么样，随时在终端敲入 <code>dsh --dump-config</code>，系统会把当前解析完成的全局抽象语法树完整打印出来，排障透明直观。</p>
